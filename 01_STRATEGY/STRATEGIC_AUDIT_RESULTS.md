## ВОПРОС 1: АУДИТ АРХИТЕКТУРЫ И УЗКИЕ ГОРЛЫШКИ

### 🔴 КРИТИЧЕСКАЯ УЯЗВИМОСТЬ №1: Telegram Bot Token в открытом JS

> [!CAUTION]
> В файле [js/app.js:734](file:///c:/Users/user/ГУГЛ%20ИМПЕРИЯ/js/app.js#L734) токен Telegram-бота `8746018179:AAHBqzasiz...` и chat_id `7655208225` **захардкожены в клиентском JavaScript**. Любой посетитель сайта может:
> 1. Извлечь токен через DevTools → Console
> 2. Рассылать спам от имени вашего бота
> 3. Читать все сообщения в чате
> 4. Удалить webhook и парализовать уведомления

**Решение:** Telegram-уведомления должны отправляться **только через серверную часть** — через Google Apps Script webhook ([LiveSheetsWebhook.gs](file:///c:/Users/user/ГУГЛ%20ИМПЕРИЯ/gas_scripts/LiveSheetsWebhook.gs)), который уже умеет вызывать `sendTelegram()`. Убрать токен из клиентского кода полностью. Фронтенд отправляет данные только на Sheets Webhook URL → Apps Script уже отправляет в Telegram.

### 🔴 КРИТИЧЕСКАЯ УЯЗВИМОСТЬ №2: Баг отступов в swarm_orchestrator.py

> [!WARNING]
> В файле [swarm_orchestrator.py:80](file:///c:/Users/user/ГУГЛ%20ИМПЕРИЯ/python_engine/swarm_orchestrator.py#L80) блок Agent 2 (Spy + Google Radar) **находится внутри `else` ветки Agent 1**. Это значит, что Agent 2 запускается **только если Agent 1 уже выполнен сегодня** (skip-ветка). При первом запуске за день Agent 2 **не вызывается вообще**. Это тихий баг, который легко пропустить.

**Решение:** Вернуть блок Agent 2 на верхний уровень с собственным `if not agent_filter` условием.

### 🟡 УЗКОЕ ГОРЛЫШКО №3: Синхронная цепочка агентов

Все 5 агентов запускаются **строго последовательно** в одном процессе Python. Если Agent 1 зависнет на сетевом запросе — вся цепочка встанет. При этом агенты 1–4 не зависят друг от друга.

**Решение (фаза 2):** Запускать агентов 1–4 через `concurrent.futures.ThreadPoolExecutor`, а Agent 5 (Spark) — после барьера `executor.shutdown(wait=True)`.

### 🟡 УЗКОЕ ГОРЛЫШКО №4: Единая точка отказа — локальный ноутбук

Вся система запускается с одного Windows-ноутбука в Одессе, где регулярные отключения электричества. `MEMORY.json` хранится локально, синхронизация с Drive — через polling демон, который тоже падает при отключении.

**Решение:**
1. **Краткосрочно (день 1–2):** Настроить `git auto-commit + push` для `_MEMORY/` каждые 30 минут через Windows Task Scheduler. GitHub становится вторым бэкапом помимо Drive.
2. **Среднесрочно (день 5–7):** Перенести cron-запуск роя в **GitHub Actions** (уже есть шаблон в `.github/workflows/swarm_cron.yml`). Рой будет работать в облаке даже при выключенном ноутбуке.

### 🟢 ЧТО СДЕЛАНО ОТЛИЧНО:
- **Атомарная запись `MEMORY.json`** через `write-to-tmp → rename` в [memory_manager.py:51-56](file:///c:/Users/user/ГУГЛ%20ИМПЕРИЯ/python_engine/memory_manager.py#L51-L56) — правильный паттерн, предотвращает повреждение файла при внезапном отключении.
- **Единоличное право записи у Agent 5** — корректная архитектура, исключает гонки потоков.
- **`agent_startup_check()` с идемпотентностью** — грамотно предотвращает дублирование работы.

## ВОПРОС 2: ПОЛНОТА ЭКСПЛУАТАЦИИ ЭКОСИСТЕМЫ GOOGLE AI 2026

### Неочевидные связки, создающие непреодолимый Tech Moat:

#### 🔗 Связка 1: Pomelli → NotebookLM → Proposal Generator (Закрытый цикл персонализации)
1. **Pomelli** сканирует сайт клиента → извлекает «Business DNA» (цвета, тон, USP).
2. **NotebookLM** принимает Business DNA как источник → становится экспертом по бизнесу клиента.
3. **Proposal Generator** использует Business DNA для генерации КП, которое **выглядит как внутренний документ компании клиента**, а не как шаблонный оффер.

**Почему это ров:** Конкурент, который просто подставляет имя клиента в шаблон, не может воспроизвести персонализацию на уровне ДНК бренда.

#### 🔗 Связка 2: Stitch → Opal → Apps Script (Мгновенный прототип → Рабочий продукт)
1. **Stitch** генерирует интерактивный UI-прототип клиентского решения за 5 минут.
2. **Opal** превращает прототип в рабочее no-code приложение.
3. **Apps Script** связывает приложение с Google Sheets/Drive клиента — всё работает на **его собственном аккаунте**.

**Почему это ров:** Весь продукт живет в экосистеме Google клиента. Нет vendor lock-in на ваш сервер. Клиент владеет всем. Это убивает главное возражение («А если вы закроетесь?»).

#### 🔗 Связка 3: Julian Goldie Radar → Agent 3 SMM → Teleprompter (Конвейер контента)
1. **Google Radar** фиксирует новый инструмент Google (например, свежий релиз Stitch 2.0).
2. **Agent 3 SMM** мгновенно генерирует 3 поста в стиле «Что значит Stitch 2.0 для вашего бизнеса».
3. **Teleprompter Studio** загружает готовый 15-сек скрипт → вы записываете Shorts за 1 дубль.

**Почему это ров:** Скорость реакции. Вы публикуете экспертный контент о новом инструменте Google **в день его выхода**, пока конкуренты еще разбираются что это такое.

### ❌ Что НЕ используется и стоит добавить:
