# 🛡 ПОЛИТИКА ПРОИЗВОДСТВЕННОЙ НАДЕЖНОСТИ (RULES_PRODUCTION.md)
## Архитектурный стандарт Sovereign Outreach & Automation (2026)

### ПРАВИЛО 1: Полный запрет моков (Zero Tolerance to Mocks)
Никаких `time.time()`, фейковых ID, синтетических ответов или заглушек в боевых интеграциях. 
Любой ID объекта (черновик, письмо, задача, строка таблицы) обязан быть подлинным идентификатором, возвращенным внешней системой (Google API, CRM, n8n).

### ПРАВИЛО 2: Реальные системные и сетевые вызовы
Все интеграции (Google Sheets API, Gmail API, FFmpeg, Playwright) обязаны выполнять реальные системные и сетевые вызовы. В случае сетевого сбоя или отказа в доступе код обязан поднимать реальное исключение (`HttpError`), а не «притворяться», что всё в порядке.

### ПРАВИЛО 3: Честный OAuth 2.0 User Consent Flow
Если API требует прав пользователя (например, доступ к личному почтовому ящику `mail.google.com`), скрипт ОБЯЗАН:
1. Задействовать официальный `google_auth_oauthlib.flow.InstalledAppFlow`.
2. Запустить локальный сервер ожидания редиректа (`run_local_server`).
3. Открыть браузер пользователя для однократной авторизации.
4. Сохранить долговременный токен (`token_gmail.json`) с `refresh_token`.
Запрещено заменять личный ящик сервисными аккаунтами без доменного делегирования, которые не имеют доступа к папке «Черновики».

### ПРАВИЛО 4: Верификация перед закрытием задачи
Работа считается завершенной **ТОЛЬКО** после успешного выполнения независимого верификационного скрипта (exit code 0), проверяющего физическое присутствие созданных данных на серверах Google.
